# The PRD: write the contract down

Once you agree, write it down. "Write a PRD for this" turns the conversation
into a project folder:

- **`prd.md`** — the contract. The problem and the solution from the user's
  side, a long list of user stories, the implementation decisions (interfaces
  and trade-offs, not file paths), how it will be tested, and what's out of
  scope and why.
- **`wip.md`** — the journal. The current focus, the phases with their
  issues, and an activity log that every session appends to.

The PRD changes only when the intent changes; the WIP changes every session.
Together they let any agent resume a project cold.

Not everything needs a project. A single fix or chore is just an issue.
